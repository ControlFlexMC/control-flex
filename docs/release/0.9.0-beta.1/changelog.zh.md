# ControlFlex 0.9.0-beta.1 Changelog

- **版本：** `0.8.9` → `0.9.0-beta.1`（`mod_version` 0.9.0-beta.1；`cfx_api_version` 0.9.2 → 0.9.2.2；`gamepad_jni_version` 0.9.4 → 0.9.6.2）

这个 beta 让 GUI 层真正能「住人」：光标与虚拟滚轮各自拿到四档速度、切分点可拖；每个界面都有了可绑定的动作菜单；径向菜单扩到 12 格并显示实时物品状态；载具可以用摇杆开了。桥接模组拿到原生动作注册与界面处理器，整合包作者拿到 `pack/` 配置层，客户端配置迁到 v7 —— 已有安装升级后手感不变。而在这所有东西底下，内置手柄库学会了认出 Linux 上运行中插上的手柄，也为「Windows 拦下它的原生 DLL」的机器准备了第二套绑定。共 13 个 Minecraft 版本、22 个 jar。

---

## 1. 光标与虚拟滚轮分档速度

- **各自四档** —— `slow` / `medium` / `fast` / `full` —— 按死区归一化后的摇杆推幅选取。光标：**1–50 px/tick**，默认 **2 / 5 / 8 / 20**。滚轮：每格 **10–500 ms**，默认 **300 / 200 / 100 / 50**（越小滚得越快）。
- **每个输入源独立 ±0.03 迟滞**，摇杆停在档位边界上不会来回跳。默认切分下满档 95% 进入、92% 退出，摇杆有点磨损也不要求推到精确的 1.0。
- **固定速度那条路一点没动。** 关掉分档，光标仍走 `cursorSpeed` 加原来的 0.35 逐轴阈值；滚轮仍走 `virtualWheelRepeatMs`。
- **滚轮会自己退回匀速**：滚轮没绑在摇杆轴上时（按键 / 十字键 / 扳机没有推幅可读），或当前 Screen / Overlay 自己设了 `virtualWheelRepeatMs` 时。GUI 与 game/overlay 的连发都经过 `WheelScrollSpeed`，两条路径不会各走一套。
- 配置：`cfx-client.json` 的 `cursorTiers` 与 `virtualWheelTiers`。

## 2. 切分点、卡片与滑块配色

- **三个切分点交给玩家。** `split1` / `split2` / `split3`（默认 **32 / 63 / 95** %）写进两个分档段；缺键回落到默认值，没动过的配置手感不变。
- **三把手切分条**出现在光标设置页与虚拟滚轮卡片上：冷暖渐变的分段配色、档位标签同色、范围标签实时更新。拖动时在邻居之间夹紧，不会把邻居顶走。
- **迟滞按更窄的那条邻带算**（最小 0.03，或窄带 / 4），薄档不会卡死，满档也不需要向上迟滞才能进入。
- **两张卡片统一成一种形状：** 标题、固定行、分段行、说明、然后是四档。固定行只在分档开启时变灰 —— 它位于开关**上方**，隐藏它会让开关在刚点完的瞬间跑到指针底下。分段块在分档关闭时折叠 —— 它位于开关下方，折叠不移动任何正在瞄准的东西，而它占的约 120 px 在绝大多数老配置（分档是关的）眼里就是六个死控件。两张卡片按最宽的标签算出同一个标签列，固定滑块与四档滑块从同一个 x 起画。
- **说明跟着状态走**，满档提示读实时的第三个切分点，不再写死 95%。
- **所有滑块改走 `GuiHelper.drawBoundedSlider`：** 控件取不到的值两侧填色（`#262626`），允许区间为灰（`#606060`），下界到旋钮那一段用控件自己的强调色 —— 光标档位用档位色，三个阈值用 `#55AAFF`，滚轮不填色、改由旋钮携带档位色。滚轮档位的边界是镜像的（间隔越大越慢），阈值边界跟随 `tap ≤ delay − step` 与 `delay + step ≤ long`，这正是拖动夹紧原本就在执行的范围。
- 文案：滚轮那一对是「固定滚轮间隔 / 分段滚轮间隔」，开关标签是「分段光标速度 / 分段滚轮间隔」；退回匀速的提示改成「某个界面」，因为它说的是任何单独设过速度的界面。

## 3. 界面动作菜单

- **每个界面最多 5 个菜单，每个 12 格**，由 `screen_menu_open_1..5` 打开。1 号菜单出厂绑在 Back（View）键的 PRESS 上，2–5 号不绑、不占键。
- **纯浮层。** 不 `setScreen`、不暂停、不丢 `hoveredSlot`：面板在 `post-screen-render` 里画，宿主界面仍归它自己的模组。输入蒙层让点击与按键到不了下面的界面，同时清掉底层的 hover —— 被面板盖住的悬停目标是隐患，所以依赖 hover 的动作不会出现在菜单里。
- **是列表，不是径向。** 径向靠的是几十次会话养成的空间记忆，而这一层装的动作每会话不到一次。一列完整动作名，摇杆滚动，A 确认，B 或松开扳机关闭。
- **候选来自界面本身：** 内建动作，加上这个界面所属模组的键。不需要预先配置，也不存在要手工同步的表。
- **设置页：** 界面设置新增 Menu 页签 —— 菜单列表、拖拽排序、名称 / 位置 / 高度 / 缩放、预览页与分栏滚动。一个菜单只放一个动作，`ScreenMenu` 里也拦一次，手改 JSON 与在页面上编辑得到同样对待；重复点击用 toast 回答，而不是先收下、以后再悄悄丢掉。
- **本页层映射新增「隐藏不生效动作」**（默认勾上）：表格只列出在本界面能生效的行。Reset 仍按未过滤的全集走，已绑定的行永远显示 —— 换了整合包的玩家必须还能把它解掉。
- **顺手理顺的：** 三个页签共用同一个 footer（页面不再像三个人各做一套）、返回标题的点击区覆盖文字而不只是那个 12 px 箭头、摇杆卡片按内容撑高、tooltip 在单词之间换行、未保存对话框把「保存并退出」放在「继续编辑」前面。

## 4. 径向菜单

- **槽位上限 8 → 12**；内置菜单仍以 8 个空槽起步。
- **槽位实时状态。** `use_item` 槽位显示背包数量（`×N`，上限 `99+`）、缺失状态、以及目标 id 未注册的未知状态（模组被删或名字打错），不再是空环。未注册的物品保留为占位槽，菜单形状不塌。
- **原版冷却**按快捷栏那种水位填充绘制，上方叠秒数；超过 90 s 只留填充不显示秒数，填充压在数量角标之上。
- **摇杆选择跟随部分推幅：** 0.20 激活、0.08 释放（都在死区之后），外加 10% 扇区迟滞，取代原来 0.5 的方形门限。
- **按语言命名。** `name` 仍是普通字符串，是所有没有覆盖的语言共用的兜底；`translations` 按语言码映射文本，且会被早于该特性的构建忽略 —— 降级不再崩客户端。查找顺序：当前语言 → 同基语言的唯一兄弟（`zh_cn` 找 `zh_tw`）→ `en_us` → `name` → 推导标签。
- **编辑器从哪读就写回哪：** 输入框以当前语言的译文或基准值起手，清空则删掉那一条。推导标签不再预填、不再持久化，改在渲染时解析，因此切换语言不用重启就能刷新圆环。
- **畸形配置能自愈。** 解析失败的 `radial_menus.json` 过去会在 load → createDefaults → load 里递归到 `StackOverflowError`；现在改名为 `radial_menus.json.bak`、换成自带默认值、只重试一次。配置版本为 **2**，内置菜单带双语名称。

## 5. 载具输入模式

- **compat 配置可以指名玩家骑乘的实体，并选定摇杆怎么送到它手上：** `vehicleInput` 取 `classes`（通配只认 `*`）与 `mode`。
- **`ANALOG`** 摇杆原值直通。**`EIGHT_WAY`** 每轴过 0.3 阈值后量化到 −1 / 0 / 1 —— 这正是「轻推一点就被读成满舵」的解药。**`WASD`** 量化后再通过 Virtual KBM 通道按下玩家自己的移动键位。
- **为什么需要 WASD：** 有些载具根本不读 `Input`。Snowy Spirit 的雪橇从脉冲推导方向标志位，Immersive Vehicles 直接轮询 `glfwGetKey` —— 对它们来说，模拟脉冲不是「弱一点」，是「完全没有」。
- **按被骑乘实体的运行时类名从 compat 层解析**，所以能只针对一个实体，而不动全局的驾驶/骑乘策略。连接级的键盘式策略优先级仍然最高。
- **注入的按键每 tick 比对、在 `finally` 里释放**，下车、开界面、手柄掉线都不会把 W 卡住。

## 6. 整合包配置层（pack）

- **层序变为 `default → mods → pack → user`。** `pack/` 由整合包作者手放；ControlFlex 从不创建、写入、备份或迁移这一层。覆盖是整文件替换，文件名必须是 `{mod_id}.json` 且严格匹配 —— `pack/JEI.json`、`pack/jei-tweaks.json` 会被跳过并打一条 WARNING。
- **Reset 回落到最近的一层**，玩家点「重置配置」回到的是这个包该有的样子，而不是官方默认。
- **`mod_versions` 不匹配的层会被丢弃，而不是加载成空配置。** 它不再占位，下层接管，模组页显示真正的适配而不是空白页。这条对四层都生效：把模组升到配置覆盖不到的版本后，页面会回落，而不是「适配了但全空」。
- **键归属改由所有声明过键的段决定** —— `inGameKeys` / `screenKeys` / `overlayKeys` —— 不再只看 `screenKeys`。少数动作会从 `KeyMapping` 分类回到它所属的模组下。
- **Reset 立即生效：** 低层配置马上回到生效槽，不用重启；该模组的逐键通道覆盖与逐屏覆盖一并清掉（仅当确实存在 user 文件时）。
- **社区自动 Apply 把 `pack/` 视为已占用**，不再覆盖作者的意图。已知边角：因 `mod_versions` 不匹配而被跳过的 `pack/` 文件仍算占用 —— 日志会写明，玩家仍可手动 Apply。
- **模组详情页显示生效配置文件路径**，「到底在用哪份」不用猜：路径倒数第二段就是层目录。

## 7. 桥接 API：原生动作与界面处理器

- `cfx-api` **0.9.2 → 0.9.2.2**。
- **原生动作注册。** 桥接模组改在 `IControlFlexPlugin.onRegisterActions` 里声明动作，不再注册伪 `KeyMapping`：自己命名空间下的 id、显示名、适配分组、所属层、可选的 Screen/Overlay 类过滤，以及一条默认绑定。这些动作不会出现在原版按键设置里，id 也不会被 compat 配置重新归属，`BindingSerializer` 还会把它们挡在全局 GUI / overlay 映射之外。
- **注册的 id 进入 `getActionIds()` 并经 `getEffectiveBinding` 解析**，所以候选构造、抑制、双击与提示查询复用既有路径，而不是长出第二套。Screen / Overlay 绑定放在编辑器本来就在写的逐屏表（`user_screen_overrides.json`）里；另开一个存储会让同一个概念有两个家，结果是 UI 里看得见、运行时打不响。
- **回调从事件流触发，不跟着每 tick 的 GUI 派发走**，所以 HOLD 绑定只触发一次、释放一次，而不是每秒 20 次。注册窗口在 `discoverPlugins` 前后打开、在 `onControlFlexReady` 之前关闭，之后再调注册器会抛异常。捕获到的绑定写进动作声明的目标类，而不是当前聚焦的类 —— 否则在设置界面里做的捕获会落到设置界面上。
- **界面处理器。** `ScreenHandlerRouter` 取代 `GuiBackRouter`：一张表同时管返回键与逐类 HUD 状态。返回键只为聚焦的那个类消费，处理器抛异常就回落成 Escape，一个类只允许一个处理器，不让两个模组抢同一次按下。
- **HUD 开关。** `hud_toggle` 是内建的跨阶段动作（GUI / OVERLAY / GAME），翻转逐类的显示/隐藏状态，写进 `config/controlflex/screen_hud_state.json`，再推给处理器。通知在写入之前，所以「应用失败」的状态不会被持久化；150 ms 冷却让 HOLD 绑定看起来不像闪烁。
- **绑定查询。** `ActionBindingProviderImpl` 按派发器用的同一层回答「现在哪个键会触发它」，包含逐屏与逐 overlay 表。「配了但打不响」现在读作未绑定，桥接模组因此画不出一个按不动的提示。`warpToGui`（把虚拟指针停到手绘高亮上）与图标皮肤预览为纯界面 UI 开放。
- **输入。** `PhaseEdgeSeed` 阻止跨阶段切换时被带过去的那次按下在新阶段再触发一次 —— X 在 MAIN 与 SCREEN 都绑 PRESS 时，界面不会再一进一出。

## 8. 配置迁移 v6 → v7

- `CfxV7Step` 把 `cursorTiers` 与 `virtualWheelTiers` 都写成 `enable = false`，对象是升级前就已有配置的玩家，于是升级后仍是固定光标速度与固定滚轮间隔。全新安装继续用四档。
- **老用户 ⟺ 存在 `profiles/*.json` 或存在 `cfx-client.json`。** `cache/`、`backup/` 与 `gamepad-selection.json` 只是运行痕迹，不算配置，所以只留下缓存的机器仍按新用户处理。保留 profile 那一支是有意的：删掉 `profiles/` 重置绑定的玩家，光标与视角设置还在，他一样会感觉到变化。
- **判定在任何写入之前求值**，并且 `JsonStep.create` 会在首启补一份最小 `cfx-client.json` —— 少了这次写入，第二次启动就会看到一个已存在的文件，把每个新用户都误判成老用户。它不会覆盖存在但解析失败的文件。
- **两段都写完整**（四档 + 三个切分点），取自运行时常量；段已存在则整段跳过，玩家在设置面板里做过的选择因此能活下来。
- **profile 格式不变：** `templateMeta.version` 仍是 **6**，只有客户端配置从 6 走到 7。`cursorSpeed` 与 `virtualWheelRepeatMs` 原样保留 —— 它们正是 `enable = false` 回落的目标。
- 新增 21 个测试与 7 份 fixture，覆盖两类用户、残缺段、损坏 JSON、只有缓存的情况，以及幂等性。

## 9. 内置运行时：cfx-gamepad-jni 0.9.6.2

这个 jar 里带着 11 MB 的 SDL3 与 JNI 原生库（压缩后约 4.4 MB），所以它们来自的那层库单独占一节：`0.9.4` → `0.9.6.2`，三个版本，其中两个修的都是「手柄凭空消失」。

- **Linux：运行中插上的手柄能被认出来。** SDL 的 Linux 摇杆驱动只在 `SDL_PumpEvents()` → `SDL_UDEV_Poll()` 里派发 udev 的设备增删；在 udev 枚举模式下它的 `Detect()` 是个空实现。本库自己没有 SDL 事件循环，于是进程运行期间插上的手柄永远发现不了 —— 只有 SDL 重新初始化（重启游戏）之后才出现。而为 hidraw 打开 libudev 恰好把这条路变成了默认。现在，既有的 `SDL_UpdateGamepads` 入口跑在 SDL 主线程上（宿主的客户端 tick）时改为泵事件循环；后台轮询线程不在主线程，仍走原来的 `SDL_UpdateGamepads()`。Android 排除在外，它的 SDL 来自启动器 APK，事件循环归启动器。没有新增原生入口，符号校验照旧通过，只重编了 Linux 的原生库。
- **Windows：原生库被拦，不再等于没有手柄。** SAC 会拦下没有云端信誉的未签名二进制，`gamepadjni.dll` 正是如此 —— 加载失败时报的是「An Application Control policy has blocked this file」/「The publisher of gamepadjni.dll could not be verified」。SAC 没有单文件放行：Defender 排除项、自签证书、WDAC 补充策略统统无效，所以过去的选择只有「关掉 SAC」或者「不用手柄」。**0.9.6.2 的做法是多带一套绑定：** 先试 JNI，加载不了就把同一份 SDL3 用 JNA direct mapping 绑上去，用的是游戏本来就在 classpath 上的那份 JNA。在报障的那台机器上，手柄因此可以在 SAC 保持开启的情况下继续使用。（SAC 也可能拦下 `SDL3.dll` 本身，那种情况本版没有解决。）
- **JNI 加载要探一次，不能只信 `System.load`。** `System.load` 只执行 `JNI_OnLoad`：导出符号比 Java 侧旧的二进制照样能加载，然后每次调用都抛。加载之后本库会调一次 `SDL_GetVersion()`，旧二进制探针不过就走 JNA 回退，而不是静默变成「没有手柄」。
- **绑定层之上什么都没变。** `GamepadJNI`、`Gamepad`、`GamepadManager`、`SystemCursor` 与 `Sdl3Source` 签名一个不动；走 JNI 的进程完全不碰 JNA 代码，ControlFlex 12 个版本仓库没有一处调用点需要改。
- **JNA 不打进 jar。** 它是 `compileOnly`，按 **3.4.0** 编译、兼容到 5.17.0，jar 不变大、也不新增运行时依赖。1.8.9 起的每个 Minecraft 版本本来就带 JNA（1.20.1 是 5.12.1），所以回退开箱可用。1.7.10 一个都没有：两条路都失败，错误里会写明原因。
- **1.7.10 仍可救：** 把 JNA jar 放到游戏类加载器看得见的地方 —— 启动器 JVM 参数里加 `-Xbootclasspath/a:/path/to/jna-5.12.1.jar`。探针走 `Class.forName`，会委托到 boot class path，所以不需要任何额外配置，回退就能生效。
- **失败会分段说明。** 两套都起不来时，错误分成三段 —— `JNI:` 加载失败原因，`JNA:` 要么是「不在 classpath 上，这一版不分发 JNA」，要么是它自己的异常，再加一条 `hint:`（JNI 消息里出现 Application Control policy 时直指 SAC）。不再是一句「Failed to load native library」。
- **排障用的后端开关：** `-Dcfx.gamepadjni.binding=jni|jna|auto`，没有该属性时读 `CFX_GAMEPADJNI_BINDING`。`jni` 不回退，`jna` 完全不试 JNI，`auto` 是默认；无法识别的值按 `auto` 处理并打一次日志。
- **JNA 路径的差异：** 字符串手工按 UTF-8 解 —— JNA 默认按平台编码，中文 Windows 上是 GBK，过去会把手柄名与错误串变成乱码。Windows 光标走 `user32.ShowCursor`，绑不上只降级光标。SDL 日志捕获**只**在 JNI 路径安装：JNA 的 `Callback` 会在 SDL 内部日志锁里、可能非 Java 线程上被调用，而那正是原生环形缓冲要避开的死锁。
- **0.9.6 本身**是第一个完全由 CI 构建、产物可复现的版本：`GLIBC_2.29` 的 Linux 下限、锁定的 Android NDK，13 个内置原生库与发布 jar 逐字节一致。

## 10. 版本覆盖与回移植

## 11. 修复

- **macOS：菜单里从手柄切到键鼠后光标不可见。** 两个缺陷叠在一起。其一，`restoreSystemCursor()` 在没开 Screen 时提前返回 —— 这对光标**模式**成立，对**图像**不成立：macOS/Linux 上系统光标是靠一张 8×8 透明 GLFW 纹理隐藏的，原版从不调 `glfwSetCursor`，于是那张透明图活过了 GUI 关闭（`reset()` 在 `mc.screen` 变 null 之后才跑），下一次 `releaseMouse()` 画出来的就是隐形光标。其二，恢复被延迟到真实鼠标事件之后一个 tick 执行，而 GLFW 的 cocoa 后端只在它认为指针位于内容区时才应用 `glfwSetInputMode()` / `glfwSetCursor()`，延迟恢复可能是一次静默空操作 —— GLFW 报 NORMAL + 箭头，`NSCursor` 却仍是隐藏/透明的。现在恢复是一个纯函数式的计划（图像 / 模式 / 强制刷新）：图像一律换回箭头，模式在 MC 未持有游戏内抓取时设为 NORMAL，非 Windows 且窗口聚焦时用同位置的 `glfwSetCursorPos()` 无条件逼出 `updateCursorImage()`，指针不动。`reset()`、`ensureActivated()`、`applyCursorMode()` 与真实鼠标 mixin 共用这套计划，所以真实鼠标输入也会清掉残留的透明纹理。诊断只在 `"bugReporting": true` 时输出。
- **Fabric：逐屏 compat 在原版界面上全部失效。** 配置键是 Mojmap 类名，而 `getClass().getName()` 返回的是中介名（`net.minecraft.class_490`），于是界面菜单、层映射、摇杆模式、光标样式、逐屏滚轮速度与逐屏覆盖全都匹配不到，表现出来只是「配置写了但没效果」。`ScreenFqns` 用类字面量建出的别名表把运行时类名翻译回配置身份（loom 会按版本重映射，所以不需要手工维护 `class_XXXX` 表），六处把活的界面类名交给 compat 的地方全部经过它，包括界面菜单的会话身份 —— 打开与 tick 必须一致，否则菜单下一 tick 就把自己关掉。`ScreenFqnsTest` 会在 `minecraft.json` 里出厂的界面键缺少运行时别名时失败。槽位全被过滤掉的已配置菜单现在会打日志，而不是保持沉默。
- **在 compat 配置里做的第一次编辑会抹掉继承来的一切。** 层是整文件覆盖，所以给 JEI 加一条 Screen 适配会写出一份空骨架，把它 22 条 `ignoreKeys` 与 9 条 `screenKeys` 全丢掉，JEI 的动作因此从界面菜单里集体消失。`ensureUserFile` 现在先把当前生效配置 fork 进 `user/` 再应用编辑，逐字节从磁盘读，`mod_name`、`home_page`、`translations` 以及这个构建还不认识的字段都能活下来。已存在的 user 文件仍原样使用；fork 只发生一次，之后那份文件就是玩家的资产。`exportUserJson` 导出的也是同一份 fork。
- **`delete_text`（默认 RT）上的组合键在输入框聚焦时被打掉。** `delete_text` 会捕获自己的按键，避免同一次按下再触发别的动作 —— 但捕获是按**按键**判定的，于是任何只是共用了被捕获按键的绑定，整体失去了 GUI 候选资格。在出厂配置下这静默杀掉了所有建在 RT 上的组合，包括 JEI 的查看配方 / 查看用途（RT+十字左 / RT+十字右），而且只在输入框聚焦时发生。`DeleteTextCapture.captures()` 现在是 `swallows()`：只有捕获集合覆盖了某个绑定的**全部**按键，该绑定才让位；更长的组合是另一类更具体的按下，组合引擎现有的 UPGRADE 会销毁那些 RT 尺寸的受害者。被捕获按键上的单键动作仍然让位 —— X = 清除键帽就是这个捕获存在的理由。代价（在没有聚焦输入框时本来就成立）：组合走完之前 RT 仍会删掉一个字符；一旦某个组合销毁了删除组合，按住 RT 不再连发，直到重新按下。屏幕键盘打开时，旧的键帽独占规则仍会打掉建在键帽按键上的组合 —— B 关掉键盘并保留焦点，从那里组合就能用。
- **分档滑块与自己的边界不符。** 档位行把「当前值到邻居之间那条窄带」画成红色、把真正取不到的一段画成灰色，滚轮面板一点红都没有，三张阈值卡片重复着同样反了的红、还带两个错边界。现在它们全部走同一个绘制助手；滚轮档位的边界是镜像的（间隔越大越慢），阈值边界跟随 `tap ≤ delay − step` 与 `delay + step ≤ long`。

## 12. 默认值 / 模板 Tuning

- 新装默认**开启**光标分档，**2 / 5 / 8 / 20** px/tick，切分 **32 / 63 / 95**。老配置迁移后分档是**关**的（v7）。
- 新装默认**开启**虚拟滚轮分档，每格 **300 / 200 / 100 / 50** ms。
- `screen_menu_open_1` = **Back（View）+ PRESS**；`screen_menu_open_2..5` 不绑。`hud_toggle` 已声明且刻意留空 —— 没有这条空条目，GUI 候选表根本不会遍历它，逐屏绑定会存得下、显示得出，却永远不派发。
- 三套模板仍是 **profile version 6**，且每个带 shift 层的模板现在都显式带 `hud_toggle` 条目；一致性测试要求所有与 shift 相关的动作都被列出。
- 内置 compat 源固定到 **0.9.0** tag —— 发布 tag 是 `0.9.0` 而不是 `0.9`，后者在 jsDelivr 与 raw.githubusercontent 上都是 404。已存在的 `sources.json` 会在下次客户端初始化时重钉，先备份，不动用户自建源。
